# 감사 문서 취급 규칙

이 저장소는 **public** 이다. 감사 보고서는 결함을 구체적으로 적는 문서이므로,
그 구체성이 그대로 공개되면 **아직 고치지 않은 결함의 익스플로잇 방법을 배포하는
형태**가 된다.

## 규칙

| 결함 상태 | 재현 상세를 어디에 두는가 |
|---|---|
| 시정 완료 | 이 저장소에 그대로 둔다. 고쳐진 결함의 재현 절차는 위험하지 않고, 기록으로서 가치가 있다 |
| **미시정 (백로그 포함)** | **비공개 저장소** `VinylStage/finance-tracker-audit-private` 에 둔다. 여기에는 분류·영향·트래킹 번호까지만 남긴다 |

"백로그로 미뤘다"는 것은 결함이 살아 있다는 뜻이므로 미시정으로 취급한다.

## 현재 분리된 항목

| 항목 | 위치 | 트래킹 |
|---|---|---|
| 부작용 있는 GET 이 csrfGuard 를 우회 (R2 §4.2) | `finance-tracker-audit-private` → `findings/M2-get-csrf-installments.md` | [#205](https://github.com/VinylStage/finance-tracker/issues/205) |

편집 전 원본 전문은 비공개 저장소의 `originals/` 에 바이트 그대로 보존돼 있다.
문서가 잘려 보이는 곳에는 그 사실과 트래킹 번호가 인용문으로 명시된다.

## 한계 — 과대평가하지 말 것

이 분리는 **패키징된 익스플로잇과 "미시정" 확인 정보**를 없앨 뿐, 결함 자체를
감추지 못한다. 애플리케이션 소스와 테스트가 모두 public 이므로 코드를 읽는 사람은
같은 결론에 도달할 수 있다. 근본 해결은 결함을 고치는 것이고, 이 규칙은 그때까지의
노출 완화책이다.
