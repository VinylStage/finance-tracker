# 마이크로카피 / 보이스톤 가이드

UI 텍스트(라벨, 버튼, 에러 메시지, 빈 상태, 확인 다이얼로그)에 일관된 기준이 없어, 같은 성격의 문구가 화면마다 다르게 쓰이고 있었다. 이 문서는 그 기준을 정한다. (이슈 #202)

기준선은 "친근하되 가벼워지지 않기"다. 이 앱은 사용자의 돈을 다루고, 되돌릴 수 없는 삭제와 덮어쓰기가 있다. 친근함이 신뢰를 깎아먹는 순간 그건 친근한 게 아니다.

## 톤 원칙

### 1. 개발자에게 하는 말을 사용자에게 보여주지 않는다

가장 자주 깨지는 원칙이다. 서버가 내려준 `{ error: '...' }` 문자열이 `client/src/lib/api.js` 의 `errorMessage()` 를 거쳐 그대로 `alert()` 에 실린다. 그래서 `from, to required` 나 `Invalid mode. Must be "append" or "overwrite"` 같은 영문 개발자 메시지가 사용자 화면에 그대로 뜬다.

사용자에게 필요한 건 파라미터 이름이 아니라 **무엇을 어떻게 고쳐야 하는지**다.

### 2. 되돌릴 수 없는 동작은 대상과 결과를 밝힌다

`삭제하시겠습니까?` 만으로는 무엇이 몇 건 지워지는지, 되돌릴 수 있는지 알 수 없다. 파괴적 동작의 확인 문구에는 세 가지가 들어가야 한다 — **무엇을**, **얼마나**, **되돌릴 수 있는지**.

되돌릴 수 있으면 굳이 겁주지 않는다. 되돌릴 수 없으면 반드시 말한다.

### 3. 빈 상태는 상태가 아니라 다음 행동을 말한다

`거래 내역이 없습니다.` 는 사용자가 이미 아는 사실을 반복한다. 빈 화면은 사용자가 무엇을 할 수 있는지 배우는 자리다. 상태 서술 대신 **다음 한 걸음**을 제안한다.

단, 필터 결과가 비어 있는 경우처럼 "비어 있는 게 정상"인 상황에서는 행동을 강요하지 않는다.

### 4. 문장 종결을 통일한다

현재 확인 다이얼로그에 `~하시겠습니까?` 와 `~계속할까요?` 가 섞여 있다. **질문은 `~할까요?`, 서술은 `~합니다`** 로 통일한다. `~하십시오`, `~하시기 바랍니다` 같은 공문서 말투는 쓰지 않는다.

### 5. 금액과 날짜는 꾸미지 않는다

숫자는 그 자체로 정보다. `무려 130만원!` 같은 수식은 사용자의 판단을 대신하려 든다. 금액은 `1,300,000원` 형식으로, 날짜는 `YYYY-MM-DD` 로 쓰고 감탄사와 이모지를 붙이지 않는다.

예외는 성취를 축하하는 자리다. 목표 달성이나 마일스톤 도달처럼 사용자가 잘한 일에는 짧게 인정해도 된다 — 다만 한 문장을 넘기지 않는다.

## Before / After

Before 는 전부 이 저장소에 **실제로 존재하는 문구**다. 지어낸 예시가 아니다.

| # | 원칙 | Before (현재) | After (제안) |
|---|---|---|---|
| 1 | 1 | `from, to required` | 조회할 기간을 선택해 주세요. |
| 2 | 1 | `from/to must be in YYYY-MM-DD format` | 날짜 형식이 올바르지 않습니다. 2026-07-27 처럼 입력해 주세요. |
| 3 | 1 | `Invalid mode. Must be "append" or "overwrite"` | 불러오기 방식을 선택해 주세요. 기존 내역에 추가하거나, 전체를 바꿀 수 있습니다. |
| 4 | 1 | `Not found` | 찾는 항목이 없습니다. 이미 삭제됐을 수 있어요. |
| 5 | 1 | `Internal server error` | 처리 중 문제가 생겼습니다. 잠시 후 다시 시도해 주세요. |
| 6 | 1 | `name, monthly_contribution, start_date required` | 상품명, 월 납입액, 시작일은 필수입니다. |
| 7 | 1 | `months must be >= 2 (2개월 미만은 일시불로 처리)` | 할부 개월수는 2개월 이상이어야 합니다. 1개월이면 일시불로 등록해 주세요. |
| 8 | 2 | `삭제하시겠습니까?` | 이 거래를 삭제할까요? 되돌릴 수 없습니다. |
| 9 | 2 | `비활성화하시겠습니까?` | 이 카테고리를 비활성화할까요? 기존 거래는 그대로 남습니다. |
| 10 | 2 | `기존 거래내역이 모두 삭제됩니다. 계속하시겠습니까?` | 거래내역 전체를 파일 내용으로 바꿉니다. 지금 있는 내역은 되돌릴 수 없습니다. 계속할까요? |
| 11 | 3 | `거래 내역이 없습니다.` | 아직 거래가 없어요. 첫 거래를 추가해 보세요. |
| 12 | 3 | `설정된 예산이 없습니다.` | 예산을 정하면 이번 달에 얼마나 썼는지 한눈에 볼 수 있어요. |
| 13 | 3 | `등록된 상품이 없습니다.` | 적금이나 저축성보험을 등록하면 만기까지 얼마나 남았는지 보여드려요. |
| 14 | 4 | `현재 카테고리·결제수단·설정값을 파일 내용으로 덮어씁니다. 계속할까요?` | (종결어미는 이미 기준에 맞음. 원칙 2 를 더해 무엇이 덮어써지는지는 유지) |
| 15 | 4 | `정말로 모든 거래내역을 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다.` | 거래내역을 전부 삭제할까요? 되돌릴 수 없습니다. |

### 표를 읽는 법

- **1~7번은 전부 같은 원인이다.** 서버 라우트의 검증 실패 메시지가 사용자에게 그대로 전달된다. 문구를 하나씩 고치는 것보다, 사용자에게 보일 메시지와 개발자용 메시지를 분리하는 편이 근본적이다.
- **8~10번**은 확인 다이얼로그다. 토씨 하나 다르지 않은 `삭제하시겠습니까?` 가 4곳(할부·거래·적금·리볼빙)에 있는데 지우는 대상은 전부 다르다. 같은 문구를 재사용하지 말고 대상을 밝힌다. 참고로 부채 화면은 `삭제하시겠습니까? 이자 이력도 함께 삭제됩니다.` 로 함께 지워지는 것을 밝히고 있어 이미 원칙 2 를 지킨 사례다.
- **11~13번**은 빈 상태다. 공통 EmptyState 컴포넌트(#197)가 들어오면 여기서 정한 문구를 그 컴포넌트의 기본값으로 쓴다.
- **14번은 이미 기준에 맞는 사례**다. 고칠 게 없다는 것도 기록해 둔다 — 가이드가 "전부 바꿔야 한다"는 뜻은 아니다.

## 자주 쓰는 문구 사전

같은 상황에 같은 문구를 쓴다. 새로 지어내기 전에 여기부터 본다.

### 확인 다이얼로그

| 상황 | 문구 |
|---|---|
| 되돌릴 수 있는 삭제 | `이 <대상>을 삭제할까요?` |
| 되돌릴 수 없는 삭제 | `이 <대상>을 삭제할까요? 되돌릴 수 없습니다.` |
| 여러 건 삭제 | `선택한 <N>건을 삭제할까요? 되돌릴 수 없습니다.` |
| 덮어쓰기 | `<대상>을 파일 내용으로 바꿉니다. 지금 있는 내용은 되돌릴 수 없습니다. 계속할까요?` |
| 비활성화 | `이 <대상>을 비활성화할까요? 기존 기록은 그대로 남습니다.` |

### 에러

| 상황 | 문구 |
|---|---|
| 필수 입력 누락 | `<항목>은 필수입니다.` |
| 형식 오류 | `<항목> 형식이 올바르지 않습니다. <예시> 처럼 입력해 주세요.` |
| 대상 없음 | `찾는 항목이 없습니다. 이미 삭제됐을 수 있어요.` |
| 서버 오류 | `처리 중 문제가 생겼습니다. 잠시 후 다시 시도해 주세요.` |
| 중복 | `이미 등록된 <대상>입니다.` |

### 빈 상태

| 상황 | 문구 |
|---|---|
| 데이터 없음(행동 유도) | `아직 <대상>이 없어요. <행동>해 보세요.` |
| 필터 결과 없음 | `조건에 맞는 <대상>이 없습니다.` |
| 선행 설정 필요 | `<설정>을 먼저 등록하면 <효과>를 볼 수 있어요.` |

### 성공

| 상황 | 문구 |
|---|---|
| 저장 완료 | `저장했습니다.` |
| 처리 완료(상세 있음) | `<동작>했습니다.` + 상세는 별도 줄에 |
| 목표 달성 | `목표 달성` |

## 금지 표현

| 쓰지 않는다 | 이유 | 대신 |
|---|---|---|
| `오류가 발생했습니다` 단독 | 사용자가 할 수 있는 일이 없다 | 원인이나 다음 행동을 함께 |
| `잘못된 요청입니다` | 사용자를 탓하는 어감 | 무엇을 고쳐야 하는지 |
| `~하십시오`, `~하시기 바랍니다` | 공문서 말투 | `~해 주세요` |
| `정말로`, `진짜로` | 겁주기. 되돌릴 수 없다는 사실만으로 충분하다 | 결과를 사실대로 |
| 영문 파라미터명 노출 | 사용자는 코드를 모른다 | 화면에 보이는 항목 이름 |
| 금액·날짜에 감탄사·이모지 | 숫자 판단을 대신하려 든다 | 숫자만 |
| `Loading...` 등 영문 잔여 | 언어 혼용 | `불러오는 중` |

## 적용 순서

이 가이드는 한 번에 전면 적용하지 않는다. 이미 열려 있는 이슈에서 해당 문구를 만질 때 함께 고친다.

- 빈 상태 문구 → 공통 EmptyState 컴포넌트(#197)에서 기본값으로 채택
- 신뢰 마이크로카피(#198) → 이 문서의 원칙 5(숫자를 꾸미지 않는다)와 원칙 1을 기준으로 작성
- 서버 에러 메시지 → 사용자용/개발자용 분리가 선행돼야 하므로 별도 이슈로 다룬다
