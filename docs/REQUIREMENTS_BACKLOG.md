# 요구사항 백로그 — 대화 로그 역추적

> **검토 요청.** 이 문서는 사람이 말로 전달한 요구사항을 기계적으로 뽑아낸 것이 아니라,
> 자연어 대화 로그를 읽어 정리한 결과다. **누락과 오해석이 있을 수 있다.**
> 특히 "이건 안 해도 돼", "나중에" 처럼 뒤에서 뒤집힌 지시는 마지막 발언만 반영했고,
> 대화에 나오지 않고 다른 경로(구두·화면 공유 등)로 전달된 요구사항은 애초에 잡히지 않는다.
> 표의 판정(구현됨/유실)에 이견이 있으면 그 행을 정본으로 고쳐 달라. 이 문서가 정본이다.

작성: 2026-08-06 · 근거 로그 범위: 2026-07-21 ~ 2026-08-06

## 1. 왜 이 문서가 생겼나

2026-08-06, 사용자가 이렇게 지적했다.

> "내가 이전에 요구했던 기능들 전부 문서화해서 기록하고있지? 레포에도 전부 문서화해서 계속 업데이트도 하고있는거 맞지?"
> "표준적인 문서기준에서 기능/비기능요구사항, 백로그 등등 전부 기록하라고 했었는지 기억이 안 나는데 만약 없다면 너가 우리가 나눈 대화들 내용을 직접 읽어서 정리해서 추가하는게 좋을거같아."

기존 `docs/REQUIREMENTS.md` 는 **구현된 코드를 역산해서 쓴 문서**다(2026-07-22 작성).
즉 "만들어진 것"의 목록이지 "요구된 것"의 목록이 아니다. 요구했지만 만들어지지 않은 것은
그 문서에 애초에 들어갈 수가 없었고, 그래서 유실을 감지하지 못했다.

이 문서는 반대 방향이다. **요구된 것에서 출발해 구현 여부를 대조한다.**

**한계 세 가지.**

1. 2026-07-24 이전의 사용자 ↔ Dispatch 대화 자체는 남아 있지 않다. 그 구간은 Dispatch 가
   작업 세션에 내린 지시문으로 대신했으므로, 사용자의 원문이 아니라 **한 번 번역된 요구사항**이다.
2. 2026-07-29 ~ 2026-08-01 구간은 로그에 사용자 발화가 없다.
3. 첨부 파일로 전달된 요구사항(업로드된 마크다운 3건)은 본문을 읽지 않고 대화 속 요약만 반영했다.

## 7. 재발 방지 제안

아래는 **제안이며, `CLAUDE.md` 반영은 사용자 승인 후에 한다.** 지금은 이 문서에만 적는다.

### 제안 1 — 요구 접수 즉시 이슈화 (권장)

사용자 메시지에 새 요구가 있으면 **그 자리에서 이슈를 만든다.** 설계가 안 끝났어도
`status:planning` 라벨로 껍데기만 먼저 만든다. 지금은 "이번 마일스톤에 넣자"고 답한 뒤
설계가 끝나야 이슈가 생기는데, 그 사이에 다음 지시가 오면 앞의 것이 밀린다.
FR-63(대시보드 월 선택)이 정확히 이 경로로 4일간 사라졌다.

### 제안 2 — 다항목 메시지는 항목 수를 세어 답한다 (권장)

한 메시지에 요구가 N개면 답신에 **"요구 N건 접수 → 이슈 N건"** 을 명시한다.
숫자가 맞지 않으면 그 자리에서 드러난다. 2026-08-02 16:07 메시지는 요구 4건에
이슈 2건이었는데, 답신이 산문이라 아무도 눈치채지 못했다.

### 제안 3 — 요구사항 백로그를 정본으로 두고 PR 마다 갱신 (권장)

이 문서(`docs/REQUIREMENTS_BACKLOG.md`)를 정본으로 삼고, 기능 PR 은 해당 FR 행의
상태를 함께 고친다. 기존 `docs/REQUIREMENTS.md` 는 구현 역산 문서이므로
**요구됐지만 안 만들어진 것을 담을 수 없다** — 유실 감지에 쓸 수 없다.

### 제안 4 — 사이클 종료마다 대화 로그 대조 감사 (권장)

마일스톤이 끝날 때 이번 감사와 같은 방식으로 로그를 훑어 백로그와 대조한다.
로그가 파일로 남아 있어(`audit.jsonl`) 자동화 여지가 있다. 사람이 기억으로
"뭐 빠진 거 없나" 를 판단하지 않게 하는 것이 목적이다.

### 제안 5 — 프로세스 요구는 감사 체크리스트에 직접 넣는다

PROC-15·PROC-16 처럼 "다음 감사 때 이것도 해라"는 요구는 이슈보다
`docs/audit/AUDIT_FRAMEWORK.md` 의 체크 항목으로 들어가야 산다.
이슈로 만들면 한 번 닫히고 끝나지만, 체크리스트에 있으면 매 사이클 돈다.

## 부록 B. 추출 재현 방법

```bash
# 1차 출처
LOG=~/Library/Application\ Support/Claude/local-agent-mode-sessions/*/*/agent/local_ditto_*/audit.jsonl

jq -r 'select(.type=="user")
       | select((.message.content|type)=="string")
       | select(.message.content | startswith("<command-") | not)
       | "\(.timestamp)\t\(.message.content)"' "$LOG"
```

`type=="user"` 이면서 본문이 배열인 레코드는 도구 결과와 시스템 리마인더이므로 제외한다.
같은 메시지가 두 번(사용자 입력 시점 / 세션 전달 시점) 기록되므로 연속 중복을 제거해야 한다.
